## Memory Organization and Management {#memory-organization-and-management}

### Definition

> **Memory management is the function of the operating system that manages main (primary) memory.**

It keeps track of which parts of memory are free or in use, decides which process gets memory, when and how much, allocates and frees memory, and moves processes between main memory and disk.

A program must be in main memory to run, but main memory is limited, so the OS must share it among the processes efficiently and protect them from one another.

### Goals of Memory Management

1. **Allocation and de-allocation** of memory to processes.
2. **Keeping track** of used and free memory.
3. **Protection:** a process must not access the memory of another process or of the OS.
4. **Sharing:** allow processes to share memory (for example, common code) when required.
5. **Efficient utilization:** reduce wasted memory (fragmentation) and keep as many processes in memory as possible (degree of multiprogramming).

### Memory Organization

Main memory is usually divided into two parts:

1. **Low memory:** the resident operating system (often together with the interrupt vector).
2. **High memory:** the user processes.

### Address Binding

A program's addresses pass through several forms:

1. **Symbolic addresses** in the source program (variable names, labels).
2. **Relocatable (relative) addresses** produced by the compiler (for example, "14 bytes from the start of this module").
3. **Absolute (physical) addresses** produced by the loader or at run time.

**Address binding** is the mapping of one address space to another.

It can happen at:

1. **Compile time:** if the memory location is known in advance, the compiler generates **absolute code**; the program must be recompiled if the location changes (example: MS-DOS `.COM` programs).
2. **Load time:** the compiler generates **relocatable code**, and the final addresses are fixed when the program is loaded.
3. **Execution (run) time:** binding is delayed until run time, so the process can be **moved** in memory while it runs. This needs hardware support (the MMU) and is used by most modern operating systems.

### Types of Addresses: Logical and Physical

1. **Logical (virtual) address:** an address generated by the **CPU** (by the program).
2. **Physical address:** the actual address in **main memory** (seen by the memory unit).

The set of all logical addresses of a program is its **logical address space**; the set of corresponding physical addresses is its **physical address space**. With compile-time and load-time binding the two are the same; with **execution-time binding they differ**.

| Basis | Logical address | Physical address |
| --- | --- | --- |
| Generated by | The CPU (program) | The MMU (computed) |
| Visibility | Seen by the user program | Never seen by the user program |
| Location | Does not exist physically | An actual location in RAM |
| Also called | Virtual address | Real address |

### Memory Management Unit (MMU) and the Relocation Register

The **MMU** is the hardware that maps logical addresses to physical addresses at run time.

In the simplest scheme, the **relocation (base) register** holds the starting physical address of the process, and its value is **added** to every logical address:

> **Physical address = Relocation register + Logical address**

**Example:** relocation register = 14000. The logical address 346 maps to 14000 + 346 = **14346**.

![Dynamic relocation: the MMU adds the relocation register 14000 to logical address 346](/diagrams/operating-systems/relocation-register.svg)

### Memory Protection: Base and Limit Registers

Each process is given a **relocation (base) register** (smallest physical address) and a **limit register** (range of logical addresses). Every logical address must be **less than the limit**; otherwise the hardware **traps** to the OS (addressing error):

1. If logical address < limit → physical address = base + logical address.
2. Otherwise → trap.

**Example:** base = 300040, limit = 120900. The process may use physical addresses 300040 to 300040 + 120900 − 1 = 420939. A logical address 125000 (≥ 120900) causes a trap.

### Types of Loading and Linking: Static and Dynamic

1. **Static loading:** the whole program is loaded into memory before it starts.
2. **Dynamic loading:** a routine is loaded **only when it is called**; unused routines (such as rarely used error handlers) are never loaded, so memory is saved.
3. **Static linking:** the linker copies all the library modules the program uses into the executable file.
4. **Dynamic linking:** only a reference (stub) to the library is placed in the program; the library is linked at run time. Many programs can share one copy of the library — for example, **DLLs** in Windows and **shared objects (`.so`)** in UNIX/Linux.

### Overlays

**Overlays** let a program larger than the available memory run: only the instructions and data needed at a given time are kept in memory; when other parts are needed, they are loaded into the space of parts no longer needed. The overlay structure is designed by the **programmer**.

### Swapping

**Swapping** temporarily moves a process from main memory to a **backing store** (fast disk) — **swap out** (roll out) — and later brings it back — **swap in** (roll in). It lets the total memory used by the processes exceed physical memory, increasing the degree of multiprogramming. In priority scheduling, a low-priority process can be swapped out so that a higher-priority process can be loaded (**roll out, roll in**).

**Swap time** is mostly **transfer time**, proportional to the amount of memory swapped:

> **Transfer time = Process size ÷ Disk transfer rate**

**Example:** a 2048 KB process and a disk transfer rate of 1 MB per second (1024 KB/s).

1. Swap out: 2048 KB ÷ 1024 KB/s = **2 s** (2000 ms).
2. Swap in: another 2 s.
3. Total swap time ≈ **4 s** (4000 ms), plus disk latency and other overhead.

## Memory Management Techniques {#memory-management-techniques}

The memory management techniques are classified as follows:

1. **Contiguous memory allocation:** each process occupies **one continuous block** of memory.
   1. **Single contiguous allocation:** only the OS and one user process are in memory (as in MS-DOS).
   2. **Fixed (static) partitioning:** memory is divided into partitions of fixed size before processes arrive.
   3. **Variable (dynamic) partitioning:** partitions are created at run time to the exact size of each process.
2. **Non-contiguous memory allocation:** a process is divided into parts that can be placed **anywhere** in memory.
   1. **Paging:** fixed-size parts (pages).
   2. **Segmentation:** variable-size, logical parts (segments).
   3. **Segmentation with paging:** segments that are themselves paged.
3. **Virtual memory:** only part of a process needs to be in memory (demand paging, demand segmentation) — see [Virtual Memory](/topics/operating-systems/virtual-memory).

| Basis | Contiguous allocation | Non-contiguous allocation |
| --- | --- | --- |
| Process placement | One continuous block | Parts in different places |
| Address translation | Simple (base + offset) | Needs a page or segment table |
| Speed | Faster | Slower (table look-up) |
| Fragmentation | Internal (fixed) or external (variable) | Internal (paging) or external (segmentation) |
| Memory use | Less efficient | More efficient |
| Examples | Fixed and variable partitioning | Paging, segmentation |

## Storage Allocation {#storage-allocation}

### Types of Partitioning (Contiguous Allocation)

In contiguous allocation, memory is partitioned in two ways:

1. **Fixed (static) partitioning**
2. **Variable (dynamic) partitioning**

#### 1. Fixed (Static) Partitioning

Main memory is divided into a fixed number of partitions (of equal or different sizes) when the system starts. The OS is in the first partition; **each other partition holds exactly one process**.

1. The **degree of multiprogramming** is limited by the **number of partitions**.
2. A process larger than the largest partition **cannot be loaded**.
3. A process smaller than its partition wastes the rest of the partition — **internal fragmentation**.

**Example:** a 3 MB process is placed in a 4 MB partition; 1 MB (25% of the partition) is wasted inside the partition.

- **Advantages:** simple to implement; little OS overhead.
- **Disadvantages:** internal fragmentation; limited multiprogramming; limit on process size.

#### 2. Variable (Dynamic) Partitioning

Partitions are not made in advance; when a process arrives, it is given **exactly as much memory as it needs**. The free blocks of memory are called **holes**.

1. **No internal fragmentation**, and no fixed limit on the number of processes or on process size (up to the free memory).
2. As processes come and go, small holes are left scattered between the allocated blocks — **external fragmentation**.

### Placement (Partition Allocation) Algorithms

When a process needs n bytes and several holes are large enough, the OS chooses one by:

1. **First fit:** allocate the **first** hole that is big enough, searching from the beginning. **Fastest**.
2. **Next fit:** like first fit, but the search starts from where the **previous search ended**.
3. **Best fit:** allocate the **smallest** hole that is big enough (the whole list must be searched). Leaves the smallest leftover hole.
4. **Worst fit:** allocate the **largest** hole (the whole list must be searched). Leaves the largest leftover hole, which may be usable later.

First fit and best fit are better than worst fit in both speed and storage use; first fit is generally the fastest.

**Example.** Free partitions (in order): **100 KB, 500 KB, 200 KB, 300 KB, 600 KB**. Processes (in order): **212 KB, 417 KB, 112 KB, 426 KB**.

| Process | First fit | Best fit | Worst fit | Next fit |
| --- | --- | --- | --- | --- |
| 212 KB | 500 KB (288 left) | 300 KB (88 left) | 600 KB (388 left) | 500 KB (288 left) |
| 417 KB | 600 KB (183 left) | 500 KB (83 left) | 500 KB (83 left) | 600 KB (183 left) |
| 112 KB | 288 KB hole of the 500 KB block (176 left) | 200 KB (88 left) | 388 KB hole of the 600 KB block (276 left) | 183 KB hole of the 600 KB block (71 left) |
| 426 KB | **Must wait** | 600 KB (174 left) | **Must wait** | **Must wait** |

![First fit, best fit and worst fit placing 212, 417, 112 and 426 KB in holes of 100, 500, 200, 300 and 600 KB](/diagrams/operating-systems/placement-algorithms.svg)

Here **best fit** is the only algorithm that allocates all four processes. (With other request patterns, first fit can succeed where best fit fails, because best fit leaves many tiny holes.)

### Fragmentation and Its Types

Fragmentation (wasted memory that cannot be used) is of two types:

1. **Internal fragmentation:** memory allocated to a process is **larger than it needs**, and the unused space **inside** the allocated block is wasted (fixed partitions, paging).
2. **External fragmentation:** the total free memory is enough for a request, but it is **not contiguous** — it is split into small holes **between** allocated blocks (variable partitions, segmentation).

| Basis | Internal fragmentation | External fragmentation |
| --- | --- | --- |
| Where the waste is | Inside an allocated block | Between allocated blocks |
| Cause | Fixed-size blocks larger than the request | Variable-size allocation and release |
| Occurs in | Fixed partitioning, paging | Variable partitioning, segmentation |
| Solution | Smaller blocks (best-fit partition) | Compaction, paging, segmentation |

**50-percent rule:** statistical analysis of first fit shows that, for N allocated blocks, about **0.5 N** blocks are lost to external fragmentation — that is, about **one-third** of memory may be unusable.

### Compaction

**Compaction** solves external fragmentation by **moving the allocated blocks together** to one end of memory so that all the free holes merge into **one large block**.

1. It is possible only if relocation is **dynamic** (done at execution time).
2. It is **expensive** — copying memory takes a lot of CPU time.

Another solution to external fragmentation is to let a process's memory be **non-contiguous** — paging and segmentation.

## Paging {#paging}

### Definition

> **Paging is a non-contiguous memory management technique in which the logical memory of a process is divided into fixed-size blocks called pages and physical memory into blocks of the same size called frames, so that any page can be loaded into any free frame.**

1. **Frames:** fixed-size blocks of **physical** memory.
2. **Pages:** blocks of **logical** memory of the **same size** as frames.
3. The page size is a **power of 2** (for example, 512 bytes to 8 KB, or 4 KB on many systems).
4. A **page table** for each process maps every page to the frame that holds it.

Paging **eliminates external fragmentation** (any free frame can be used), but it can cause **internal fragmentation** in the last page of a process.

### Address Translation in Paging

Every logical address is divided into two parts:

1. **Page number (p):** an index into the page table.
2. **Page offset (d):** the position of the word within the page.

The page table gives the **frame number (f)**, and the physical address is formed from f and d:

> **p = Logical address ÷ Page size (integer division)**, **d = Logical address mod Page size**
>
> **Physical address = f × Page size + d**

If the logical address space has 2ᵐ addresses and the page size is 2ⁿ, the high-order **m − n** bits are the page number and the low-order **n** bits are the offset.

```text
Logical address:   | page number p (m − n bits) | offset d (n bits) |
                                 │
                       page table [p] = f
                                 ▼
Physical address:  | frame number f             | offset d (n bits) |
```

**Example 1 (translation).** Page size = 1 KB (1024 bytes). The page table of a process is:

| Page | Frame |
| --- | --- |
| 0 | 5 |
| 1 | 2 |
| 2 | 9 |
| 3 | 12 |

Translate the logical address **2148**:

1. p = 2148 ÷ 1024 = **2** (integer part), d = 2148 − 2 × 1024 = **100**.
2. Page 2 is in frame **9**.
3. Physical address = 9 × 1024 + 100 = 9216 + 100 = **9316**.

![Paging hardware translating logical address 2148 (page 2, offset 100) to physical address 9316 (frame 9)](/diagrams/operating-systems/paging-hardware.svg)

**Example 2 (address bits).** A logical address space has **512 pages** of **2 KB** each, and physical memory has **128 frames**.

1. Page size = 2 KB = 2¹¹ bytes → offset = **11 bits**.
2. 512 pages = 2⁹ → page number = **9 bits** → logical address = 9 + 11 = **20 bits**.
3. 128 frames = 2⁷ → frame number = **7 bits** → physical address = 7 + 11 = **18 bits**.

**Example 3 (page table size).** A 32-bit logical address, 4 KB pages and 4-byte page-table entries:

1. Number of pages = 2³² ÷ 2¹² = **2²⁰** (about one million).
2. Page table size = 2²⁰ × 4 bytes = 2²² bytes = **4 MB** per process.

**Example 4 (internal fragmentation).** A process of 72,766 bytes with a page size of 2,048 bytes:

1. 72,766 ÷ 2,048 = 35 pages, remainder 1,086 bytes.
2. The process needs **36 frames**; the last frame holds only 1,086 bytes.
3. Internal fragmentation = 2,048 − 1,086 = **962 bytes**.

(In the worst case, internal fragmentation is almost one whole frame; on average it is half a page per process.)

### Page Table Entry

Besides the frame number, a page-table entry has control bits:

1. **Valid/invalid (present) bit:** whether the page belongs to the process (and is in memory).
2. **Protection bits:** read, write, execute permissions.
3. **Reference bit:** whether the page has been accessed recently.
4. **Dirty (modified) bit:** whether the page has been changed.

The OS also keeps a **frame table** that records which frames are free and which are allocated.

### Implementation of the Page Table and the TLB

1. A small page table can be kept in **registers** (fast, but only for small tables).
2. Normally the page table is kept in **main memory**, and a **Page-Table Base Register (PTBR)** points to it. Then every memory reference needs **two memory accesses** (one for the page-table entry and one for the data) — memory access becomes twice as slow.
3. The solution is the **Translation Look-aside Buffer (TLB)**: a small, fast, **associative** hardware cache that holds recently used page-number → frame-number pairs.
   1. **TLB hit:** the frame number is found in the TLB — only one memory access is needed.
   2. **TLB miss:** the page table in memory is consulted, and the pair is added to the TLB.
![Paging hardware with a TLB: on a hit the frame comes from the TLB, on a miss from the page table](/diagrams/operating-systems/paging-tlb.svg)

4. The percentage of times a page number is found in the TLB is the **hit ratio**.

**Effective Access Time (EAT):**

> **EAT = h × (t + m) + (1 − h) × (t + 2m)**

where:

- **h** = TLB hit ratio,
- **t** = TLB access time,
- **m** = main-memory access time.

On a hit, the TLB is searched (t) and memory is accessed once (m); on a miss, the TLB is searched (t), the page table is read (m) and then the data is read (m).

**Example:** h = 90%, t = 30 ns, m = 150 ns.

1. Hit time = 30 + 150 = 180 ns.
2. Miss time = 30 + 2 × 150 = 330 ns.
3. EAT = 0.9 × 180 + 0.1 × 330 = 162 + 33 = **195 ns**.
4. Slowdown compared with one plain memory access = (195 − 150) ÷ 150 × 100 = **30%**.

**Second example:** h = 90%, t = 10 ns, m = 100 ns → EAT = 0.9 × 110 + 0.1 × 210 = 99 + 21 = **120 ns**.

Without a TLB, each access would take 2m (300 ns in the first example).

### Advantages and Disadvantages of Paging

- **Advantages:** no external fragmentation; no need for contiguous memory; simple allocation (any free frame); easy swapping because pages and frames are the same size; supports virtual memory and sharing of common code.
- **Disadvantages:** internal fragmentation in the last page; the page table needs memory (it can be large); every access needs a table look-up (two memory accesses without a TLB); more complex hardware.

### Structures for Large Page Tables

1. **Hierarchical (multilevel) paging:** the page table itself is paged (two-level or three-level page tables), so only the parts in use need to be in memory.
2. **Hashed page table:** the page number is hashed into a table of linked lists (used for address spaces larger than 32 bits).
3. **Inverted page table:** one entry per **physical frame** (not per page), holding the process ID and page number; it saves memory but makes look-up slower.

## Segmentation {#segmentation}

### Definition

> **Segmentation is a non-contiguous memory management technique in which a program is divided into variable-size logical units called segments, such as the main program, functions, stack, global variables and arrays.**

Segmentation supports the **user's view** of a program as a collection of logical parts. Each segment has a **name (number)** and a **length**, and a logical address is a pair:

> **⟨segment number s, offset d⟩**

### Segment Table

Each process has a **segment table**; each entry has:

1. **Base:** the starting physical address of the segment.
2. **Limit:** the length of the segment.

The **Segment-Table Base Register (STBR)** points to the segment table in memory, and the **Segment-Table Length Register (STLR)** holds the number of segments (a segment number s is legal only if s < STLR).

### Address Translation in Segmentation

1. The segment number s indexes the segment table to get the base and limit.
2. The offset d is checked: **0 ≤ d < limit**.
3. If the check is true, **physical address = base + d**.
4. If d ≥ limit, the hardware **traps** to the OS (addressing error / segmentation fault).

**Example.** Segment table:

| Segment | Base | Limit |
| --- | --- | --- |
| 0 | 1400 | 1000 |
| 1 | 6300 | 400 |
| 2 | 4300 | 400 |
| 3 | 3200 | 1100 |
| 4 | 4700 | 1000 |

| Logical address ⟨s, d⟩ | Check d < limit | Physical address |
| --- | --- | --- |
| ⟨2, 53⟩ | 53 < 400 ✓ | 4300 + 53 = **4353** |
| ⟨3, 852⟩ | 852 < 1100 ✓ | 3200 + 852 = **4052** |
| ⟨1, 399⟩ | 399 < 400 ✓ | 6300 + 399 = **6699** |
| ⟨0, 1222⟩ | 1222 < 1000 ✗ | **Trap** (segment 0 is only 1000 bytes long) |

![Segmentation hardware: the offset is compared with the limit and added to the base](/diagrams/operating-systems/segmentation-hardware.svg)

### Types of Segmentation

1. **Simple segmentation:** all the segments of a process are loaded into memory (not necessarily contiguously).
2. **Virtual-memory segmentation:** segments are loaded only when needed (demand segmentation).

### Advantages and Disadvantages of Segmentation

- **Advantages:** no internal fragmentation; matches the programmer's logical view; segments can have different **protection** (for example, code read-only) and can be **shared**; segments can grow (stack, heap); the segment table is smaller than a page table.
- **Disadvantages:** **external fragmentation** (segments have different sizes); compaction may be needed; more complex memory allocation; each access needs a segment-table look-up.

### Paging vs Segmentation

| Basis | Paging | Segmentation |
| --- | --- | --- |
| Size of blocks | Fixed-size pages | Variable-size segments |
| Division done by | The OS (hardware decides page size) | The compiler/programmer (logical units) |
| User's view | Invisible to the programmer | Matches the programmer's view |
| Logical address | Page number + offset (one-dimensional) | Segment number + offset (two-dimensional) |
| Table | Page table (frame number) | Segment table (base and limit) |
| Fragmentation | Internal | External |
| Protection and sharing | Harder (per page) | Easier (per logical unit) |
| Speed | Faster | Slower |

### Segmentation with Paging

**Segmented paging** combines both: memory is divided into segments, and each segment is divided into **pages**. A logical address is ⟨segment number, page number, offset⟩. The segment table gives the address of the segment's **page table**, and the page table gives the frame. It keeps the logical view of segmentation and removes the external fragmentation of segmentation. (Intel x86 processors use segmentation with paging.)

## Address Mapping {#address-mapping}

**Address mapping (address translation)** is the conversion of the logical address generated by the CPU into the physical address in memory.

It is done by the **MMU** at run time, and the method depends on the memory-management technique.

### 1. Contiguous Allocation (Relocation and Limit Registers)

> **If logical address < limit, physical address = relocation (base) register + logical address; otherwise trap.**

**Example:** base = 14000, limit = 5000. Logical 346 → 14000 + 346 = **14346**. Logical 6000 → 6000 ≥ 5000 → **trap**.

### 2. Paging

> **Physical address = (frame number of page p) × page size + offset d**

Example: page size 1 KB, page 2 in frame 9, logical address 2148 → p = 2, d = 100 → **9316** (see [Paging](#paging)).

### 3. Segmentation

> **If d < limit of segment s, physical address = base of segment s + d; otherwise trap.**

Example: ⟨2, 53⟩ with base 4300 and limit 400 → **4353** (see [Segmentation](#segmentation)).

### 4. Segmentation with Paging

1. The segment number selects the segment's page table (and the offset is checked against the segment limit).
2. The page number selects the frame in that page table.
3. Physical address = frame number × page size + page offset.

### 5. Using a TLB

The page number is first looked up in the **TLB**; on a hit the frame number is used at once, on a miss the page table in memory is read (see the EAT formula in [Paging](#paging)).

### Summary

| Technique | Logical address | Mapping hardware/table | Physical address |
| --- | --- | --- | --- |
| Contiguous | Single offset | Relocation and limit registers | Base + offset (if offset < limit) |
| Paging | ⟨page p, offset d⟩ | Page table (and TLB) | Frame × page size + d |
| Segmentation | ⟨segment s, offset d⟩ | Segment table (base, limit) | Base + d (if d < limit) |
| Segmented paging | ⟨s, p, d⟩ | Segment table + page tables | Frame × page size + d |
